# CPU in five steps — 2026-11-05

YouKnow 1.4.6 removes work from the engine's audio path in five commits, each leaving every rendered sample identical. The baseline is `5b3ea97` (1.4.5). This is an unreleased source change measured on a development container; no installed plug-in or Rack Extension was replaced and nothing here is a Reason-host measurement.

## Where the time went

After the 1.3.4 and 1.4.2 rounds the Rack-build profile is flat: the VCF's RK4 solve is about 28 % of a six-voice block, the chorus 13 %, the two emulated firmware CPUs about 9 %, `pow` in the cutoff law and soft clip 4 %, and nothing else above 3 %. What remained was mostly overhead around the model rather than the model itself: library calls the Rack's `-fno-builtin` leaves as real calls, float/double conversions on FIR taps, re-validation, and calls to small functions on per-instruction and per-interval paths.

## Changes

1. **Inline square roots under Clang** (`08b4b77`). The 1.3.4 `inlineSqrt` names `__builtin_sqrt`, which GCC inlines; Clang under `-fno-builtin` still lowers it to libm's `sqrt` while `errno` is observable. Clang now uses `__builtin_elementwise_sqrt`, the same correctly rounded instruction without `errno`. The output-summer clip, the closed-loop spectral factor, the chorus mute drive and bucket noise, the coupled mixer, the C41 noise and the output jack use it.
2. **FIR transport rings held as doubles** (`c9ccbf7`). The voice-island, output-summer and chorus-island transports stored float samples and widened every tap to double. They now store the same float values as doubles, so the taps read them directly. A float converts to double exactly, so the products are unchanged.
3. **No repeated UART checks in the firmware scheduler** (`90484e2`). `FirmwareAssignerScheduler::advanceTo` validates the UART at entry, then advanced it once per emulated instruction through the public `advanceTo`, which validated the same state again. The loop now calls `Uart::advanceToPrechecked`, the unchanged advance body. The FIR decimation pairs also store their mirrored tap.
4. **Call overhead off per-instruction and per-interval paths** (`321ad10`). The voice CPU's complete/arbitrate/begin/ADC steps are always inlined into its run loop. The scheduler's per-instruction UART advance settles inline when no UART event is due. The converter interval tests the DCO-hold and VCA-junction-initialisation guards before calling.
5. **The remaining small per-step calls** (`8897ad9`). The voice CPU's decode, peripheral-access and stack-event steps are inlined, and so is `VcaControlReconstruction::sample`, read once per local VCA interval.

Circuit equations, kernels, tableaux, processing rates, latency, noise laws, random draws and the firmware's observable behaviour are unchanged.

## Instruction counts

The 1.4.2 harness (`cpu-settled-2026-10-30/bench.cpp`): A11 Brass Set 1, 48 kHz, Normal Circuit Rate, Original timing, chorus II, 64-frame callbacks, 200 measured callbacks under `valgrind --tool=callgrind --collect-atstart=no`. Settled is `YK_SETTLED=1 YK_WARM=3000`. Compiled as the Rack does: C++17, `-O3 -fno-builtin -DYOUKNOW_EMBEDDED_TARGET=1`, Clang 18.1.3, x86-64. Instructions per 64-frame callback:

| Commit | Settled idle | Settled six voices | Cold six voices |
| --- | ---: | ---: | ---: |
| baseline 1.4.5 | 3,358,708 | 5,676,762 | 5,877,165 |
| 1. Inline square roots | 3,335,252 | 5,630,908 | 5,831,142 |
| 2. FIR rings as doubles | 3,321,683 | 5,553,591 | 5,753,849 |
| 3. UART checks | 3,277,104 | 5,498,717 | 5,698,965 |
| 4. Call overhead | 3,220,223 | 5,441,987 | 5,642,231 |
| 5. Small per-step calls | 3,214,307 | 5,425,795 | 5,626,050 |
| **1.4.6 against 1.4.5** | **−4.3 %** | **−4.4 %** | **−4.3 %** |

Every row's three stream hashes (FNV-1a over every output sample) equal the baseline's: `856316cff88d1191` idle, `b1aa9ad6bb7cf7de` settled six voices, `9fd57837ca3f0667` cold six voices.

Tried and left out, because they cost instructions or saved under 0.1 %: skipping the island's trajectory interpolation when a node set is flat (it almost never is), deferring the service temperature on the island shot-noise path, forcing the VCA junction table sample, the stage-noise reconstruction or the chorus mute-drive steps inline (GCC also refuses `always_inline` on the latter's out-of-line definitions), and a one-entry memo of the sub-level diode solve (no repeated voltage in 1M calls).

## Audio parity

`cpu-settled-2026-10-30/nulltest.cpp`, Clang with the Rack flags, thermally settled (`YK_SETTLED=1 YK_PREROLL=3`): **all 144 presets bit-identical** to the 1.4.5 baseline (`compare_null.py`: 144 of 144 bit-exact, every residual −999 dB). The null-test candidate was built before step 5 dropped its chorus inlining attributes, which change no arithmetic; the final tree's stream hashes are those in the table.

## Tests

The DSP test tree (`-DYOUKNOW_BUILD_PLUGIN=OFF -DBUILD_TESTING=ON`, Release, GCC 13, x86-64), on the final tree:

- `YouKnowDSPCxx17` built.
- `unit` 132/132 passed.
- `audio` 2/2 passed (`YouKnow.AudioDemos`, `YouKnow.MoreDemos`).
- `perf` 2/2 passed (`YouKnow.EnginePerformance`, `YouKnow.CpuBudget`), run on its own.

## Reproduce

```sh
H=Docs/benchmarks/cpu-settled-2026-10-30
CXX=clang++ $H/build.sh /path/to/1.4.5-checkout bench /tmp/bench-baseline rack
CXX=clang++ $H/build.sh . bench /tmp/bench-candidate rack
YK_SETTLED=1 YK_WARM=3000 YK_NOTES=6 valgrind --tool=callgrind --collect-atstart=no /tmp/bench-candidate original 48000 normal 200 2 1 0
CXX=clang++ $H/build.sh /path/to/1.4.5-checkout nulltest /tmp/nulltest-baseline rack
CXX=clang++ $H/build.sh . nulltest /tmp/nulltest-candidate rack
YK_SETTLED=1 YK_PREROLL=3 $H/null.sh /tmp/nulltest-baseline /tmp/null-base
YK_SETTLED=1 YK_PREROLL=3 $H/null.sh /tmp/nulltest-candidate /tmp/null-cand
python3 -I Docs/benchmarks/cpu-trims-2026-10-23/compare_null.py /tmp/null-base /tmp/null-cand --csv /tmp/null.csv
```
