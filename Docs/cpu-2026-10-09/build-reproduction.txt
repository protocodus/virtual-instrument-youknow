Build both revisions with the same compiler, Release flags and IPO policy.
The recorded baseline is a0c6b08c0375b325f169e4dae7ece776081395b5. The candidate
is the source change accompanying this report; its DSP hashes are in manifest.json.
Use separate source/build directories so each executable uses its own headers.

cmake -S /path/to/source -B /path/to/build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++ \
  -DCMAKE_INTERPROCEDURAL_OPTIMIZATION_RELEASE=ON \
  -DYOUKNOW_BUILD_PLUGIN=OFF -DYOUKNOW_BUILD_TOOLS=ON \
  -DYOUKNOW_HARDWARE_REALISM_CANDIDATE=ON -DBUILD_TESTING=ON
cmake --build /path/to/build --target YouKnowOversamplingAudit -j 2

The measured toolchain was GCC 14.2.0 on Linux x86-64. No fast-math flags or
native-machine instruction flags were added. The source defaults enable IPO
for Release when supported; the command above makes that policy explicit.
The plugin build is disabled for these native DSP measurements.

See render-reproduction.txt for the separate audio fixture link commands and
the three evidence drivers for steady-state timing, transition timing and
audio comparison. Use new output directories to preserve existing evidence.
CPU comparisons must run serially, after builds and other tests have stopped.

The candidate validation also builds the relevant CTest executables and runs:
YouKnow.ChorusNonlinear, YouKnow.ChorusDenseInput, YouKnow.ChorusOutputRecovery,
YouKnow.FirmwareAssignerScheduler, YouKnow.OriginalPerformance,
YouKnow.FirmwareLiveAssignerAudio, YouKnow.VcaJunctionTemperature,
YouKnow.HardwareRealismProfile, and the full YouKnow.Engine suite. The full
engine suite can take about fourteen minutes on this environment; a 1200-second
